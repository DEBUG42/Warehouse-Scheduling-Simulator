# 物流仓库仿真系统 GUI 开发思考过程

## 项目整体理解与信息流分析

### 1. 项目概述

这是一个基于 SFML 2.6 和 C++的物流仓库 3D 仿真系统，主要用于模拟环形轨道穿梭车系统。系统由前端（GUI 展示）和后端（仿真引擎、算法）两部分组成。我负责的是前端 GUI 部分，需要精确地展示轨道、仓库和物流小车，并与后端保持良好的通信。

### 2. 坐标系统与尺寸设计

从文档中了解到：

- 原点(0,0)位于轨道左侧弯道中心
- X 轴水平向右为正，Y 轴垂直向上为正
- 使用毫米(mm)作为实际单位
- 转换比例：1mm = 0.05px（像素）
- 轨道由两段直线(各 40000mm)和两段弯道(半径 2500mm)组成
- 小车长度为 2000mm，宽度需自定义

### 3. 前后端通信需求

前后端通信主要包括以下内容：

1. 小车数量信息（后端告知前端有几辆小车）
2. 小车位置信息（每辆小车的总路程，从左下角弯道与直道交界处为原点，逆时针方向）
3. 仿真控制信息（倍速、启停状态）

### 4. 已有代码组织结构分析

项目采用面向对象的结构，主要类包括：

- `MainWindow`：主窗口管理，处理事件循环和布局
- `SimulationView`：仿真场景视图，管理视图变换和对象选择
- `TrackRenderer`：轨道渲染器，负责绘制轨道形状
- `VehicleRenderer`：车辆渲染器，负责绘制小车
- 新增 `WarehouseRenderer`：仓库渲染器，负责绘制仓库/接口设备
- 新增 `SimulationInterface`：前后端通信接口，定义数据交换格式
- 新增 `MockSimulationInterface`：模拟仿真接口，用于 GUI 开发测试

### 5. 信息流传递分析

信息流主要分为两个方向：

**后端 -> 前端:**

1. 小车状态更新（位置、速度、载货状态）
2. 设备状态更新（入库口、出库口、接口设备的状态）
3. 仿真参数（时间、倍速、暂停/运行）

**前端 -> 后端:**

1. 仿真控制命令（启动、暂停、设置速度）
2. 用户交互反馈（如选中车辆、查看详情）

### 6. 目录结构规划

项目在 `/Warehouse-sch/GUI` 目录下进行开发，主要包含以下文件结构：

- 核心渲染组件：TrackRenderer_fixed、VehicleRenderer、WarehouseRenderer
- 通信接口：SimulationInterface、MockSimulationInterface
- 视图控制：SimulationView、MainWindow
- 程序入口：main.cpp、main_simplified.cpp（简化版本）
- 构建系统：CMakeLists.txt、build.ps1
- 文档：docs目录下的各种说明文档

需要注意，该项目之前有多个实验性代码目录，包括 `/Warehouse-sch/homework/GUI`，在开发过程中需要确保代码集中在主要的 `/Warehouse-sch/GUI` 目录下，以保持项目结构清晰。

1. 用户操作（开始/暂停仿真、调整倍速）
2. 视图控制（缩放、平移、选择对象）

### 6. 3D 效果实现思路

由于使用 SFML（2D 库）实现 3D 效果，需要采用"伪 3D"技术：

- 使用斜视投影方法（例如 X'=X+0.5*Z, Y'=Y-0.5*Z）
- 利用物体重叠关系、阴影、立体边框等视觉元素增强深度感
- 小车和仓库的绘制采用多层叠加技术，形成立体感

## 前后端通信详细设计

根据项目需求，前后端通信接口必须处理以下数据：

### 1. 车辆状态信息

```cpp
struct VehicleState {
    int id;                      // 车辆ID
    float position;              // 总路程（mm）
    float speed;                 // 当前速度（m/s）
    MotionState motionState;     // 运动状态（停止/运动/加速/减速）
    bool isLoaded;               // 载货状态
    int currentTaskId;           // 当前任务ID（-1表示无任务）
};
```

### 2. 设备状态信息

```cpp
struct DeviceState {
    int id;                      // 设备ID
    DeviceType type;             // 设备类型（入库口/出库口/入库接口/出库接口）
    DeviceStatus status;         // 设备状态（空闲/繁忙/故障）
    int queuedTaskCount;         // 队列任务数
    float processingProgress;    // 处理进度(0.0-1.0)
};
```

### 3. 仿真控制信息

```cpp
struct SimulationState {
    bool isPaused;               // 是否暂停
    SimulationSpeed speed;       // 仿真速度（枚举：0.5x/1x/2x/5x/10x）
    float simulationTime;        // 仿真时间(s)
    int vehicleCount;            // 车辆数量
    int completedTaskCount;      // 已完成任务数量
    int pendingTaskCount;        // 待处理任务数量
};
```

### 4. 回调机制设计

采用回调函数机制，使前端可以及时响应后端状态变化：

```cpp
using StateUpdateCallback = std::function<void(const SimulationState&)>;
using VehicleUpdateCallback = std::function<void(const std::vector<VehicleState>&)>;
using DeviceUpdateCallback = std::function<void(const std::vector<DeviceState>&)>;
```

这种设计使前端和后端可以松耦合，各自专注于自己的职责，同时保持数据的实时同步。
